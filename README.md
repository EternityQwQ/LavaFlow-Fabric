LavaFlow is an experimental Vulkan 1.1 graphics backend for Minecraft's Blaze3D API. It replaces the exercised Blaze3D rendering path with LavaFlow-owned LWJGL Vulkan implementations and never calls OpenGL.

## Compatibility

| Component | Target |
| --- | --- |
| Minecraft | 26.2 |
| Mod loader | Fabric Loader 0.19.3 or newer |
| Minecraft runtime | Java 25 |
| Graphics API | Vulkan 1.1 |
| Desktop smoke renderer | Java 21 bytecode |

The backend includes compatibility paths for Vulkan 1.1 devices without dynamic rendering, synchronization2, push descriptors, multi-draw indirect, non-solid fill mode, or vertex attribute divisors. Both desktop and ARM64 Android devices are in scope. Actual driver behavior and performance vary by GPU.

## Current Features

- LavaFlow-owned Vulkan instance, presentation device, queues, and swapchain
- Blaze3D textures, buffers, samplers, pipelines, render passes, and command encoding
- Dynamic-rendering and legacy-render-pass paths
- Push-descriptor and descriptor-set paths
- Explicit resource lifetime and queue synchronization
- Vulkan-native texture transfers, blits, clears, and presentation
- Resize and swapchain recreation handling
- Final presentation blit with the target Y coordinate reversed
- Sodium 0.9.1 compatibility: Sodium's Vulkan terrain path runs on LavaFlow instead of falling back to OpenGL

LavaFlow uses clockwise front faces and does not enable shaderc's invert-Y option. These conventions are required to match Minecraft's official Vulkan backend behavior.

## Architecture

```text
Minecraft Blaze3D API
        |
LavaFlow Fabric adapter (dev.lavaflow.minecraft)
        |
LavaFlow Vulkan backend (dev.lavaflow.vulkan)
        |
Vulkan 1.1
```

The Minecraft-facing adapter lives under `dev.lavaflow.minecraft`. The standalone Vulkan renderer under `dev.lavaflow.vulkan` contains no Minecraft classes, keeping Vulkan resource ownership and batching policy independent of Minecraft.

### Source layout

| Path | Responsibility |
| --- | --- |
| `src/main/java/dev/lavaflow/vulkan/` | Standalone Vulkan core: instance/device/swapchain (`LavaFlowRenderer`, `FrameResources`, `QueueFamilies`, `SwapchainState`, `SwapchainSupport`, `VulkanException`). No Minecraft classes. |
| `src/main/java/dev/lavaflow/smoke/` | `LavaFlowSmoke`, a standalone GLFW + Vulkan clear-loop used to validate the backend without Minecraft. |
| `src/minecraft/java/dev/lavaflow/minecraft/` | Fabric adapter. `LavaFlowBackend` implements Blaze3D's `GpuBackend`; `vulkan/` holds the Blaze3D Vulkan implementations (`LavaFlowDevice`, `LavaFlowGpuBuffer`, `LavaFlowGpuTexture`, `LavaFlowRenderPass`, `LavaFlowRenderPipeline`, `LavaFlowCommandEncoder`, `LavaFlowDescriptorCache`, `LavaFlowShaderc`, `LavaFlowVulkanPass`, ...). |
| `src/minecraft/java/dev/lavaflow/minecraft/mixin/` | Core mixins: `PreferredGraphicsApiMixin` selects LavaFlow as the backend; `FramerateLimitMixin` and `FrameStatsMixin` are development-only instrumentation gated by system properties. |
| `src/minecraft/java/dev/lavaflow/minecraft/sodium/` | Sodium 0.9.1 compatibility. `LavaFlowSodium` exposes LavaFlow's device/pass to Sodium; `DrawBackendMixin` routes Sodium onto its Vulkan path; `VKDrawContextMixin` binds LavaFlow's command buffer and pipeline layout; the accessors read Blaze3D's backend fields. |
| `src/sodiumStub/java/` | Compile-time signature stubs for Sodium (`net.caffeinemc.*`). Never packaged; Sodium supplies the real classes at runtime. |
| `src/minecraft/resources/` | `fabric.mod.json` and the mixin configs (`lavaflow.mixins.json`, `lavaflow-sodium.mixins.json`). |
| `src/minecraft-test/java/`, `src/test/java/` | Unit tests for the Vulkan remapping (`LavaFlowVkTest`, `LavaFlowPushConstantsTest`) and queue-family logic (`QueueFamiliesTest`). |

### Sodium compatibility notes

Sodium selects its backend by testing for Minecraft's own `VulkanDevice`, so a foreign Vulkan backend would otherwise be treated as OpenGL. LavaFlow selects the indirect Vulkan path, built on core `vkCmdDrawIndexedIndirect` (no device extension required), and prefers the interleaved multi-draw path when the device reports it as available.

## Building

Prerequisites:

- JDK 25
- Vulkan 1.1 loader and driver
- Gradle 9.5.1 or a compatible Gradle release

Fabric Loom downloads the Minecraft 26.2 client automatically on first build.

Build and test the project:

```sh
gradle --no-daemon clean test jar
```

The Fabric mod is written to:

```text
build/libs/lavaflow-0.1.0-alpha.jar
```

GitHub Actions runs the same build for pushes, pull requests, and manual dispatches, then publishes the JAR as a workflow artifact.

## Smoke Renderer

Run the standalone Vulkan smoke renderer with:

```sh
gradle run
```

For a finite automated run:

```sh
gradle run --args='--frames=120'
```

The window should clear continuously through Vulkan and report the selected GPU and frame count in its title. Closing it exercises orderly resource teardown.

## Installing on Fabric

1. Copy `build/libs/lavaflow-0.1.0-alpha.jar` to the Minecraft 26.2 instance's `mods` directory.
2. Select Vulkan as the instance graphics backend.
3. Start Minecraft with Java 25.

For FCL on Android, the typical mod path is:

```text
/storage/emulated/0/FCL/.minecraft/versions/26.2-Fabric/mods/
```

The exact instance directory can differ between launcher configurations.

## Status

LavaFlow is experimental software. Rendering correctness and performance have been tested on a limited set of desktop and ARM64 devices, but Vulkan driver differences can expose device-specific issues. Keep a known-good JAR when testing new builds.
